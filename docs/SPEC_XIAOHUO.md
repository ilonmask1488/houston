# ТЗ: приложение для изучения разговорного китайского «小火 / Сяо Хо»

Этот документ — техническое задание для Claude Code. Прочитай его целиком, прежде чем писать код. Реализуй по фазам (раздел 16), после каждой фазы останавливайся и показывай результат.

---

## 1. Для кого и зачем

**Пользователь** — один человек, русскоязычный студент-инженер (ракетно-космическая специальность, 4 курс).

- Китайский **с нуля**.
- Цель — **работа и карьера**: говорить с китайскими коллегами, пережить командировку, потом сдать HSK для резюме.
- Время — **30–45 минут в день**.
- Главное — **говорить и понимать на слух**. Иероглифы вторичны и вводятся постепенно.
- Основное устройство — **телефон**, иногда компьютер.
- **Обучение должно быть весёлым.** Монотонность — главный враг: если станет скучно, пользователь бросит. Это требование того же уровня, что и корректность языка (см. раздел 6).

**Цель приложения** — ежедневная тренировка: тоны, произношение, слова, фразы, аудирование, шэдоуинг, сюжетные диалоги. Объяснения грамматики и свободный разговор пользователь получает в чате с Claude, приложение помогает туда переходить (раздел 12).

**Ориентир по результату:** примерно через 12 месяцев уровень HSK 3 и уверенный бытовой и базовый рабочий разговор.

## 2. Принципы

1. **Сначала звук, потом знак.** Первые 2–3 недели — только пиньинь и тоны. Иероглифы видны, но не требуются.
2. **Тоны везде.** Любое слово и любая фраза показываются с тонами и воспроизводятся аудио. Нет упражнения без звука.
3. **Говорить вслух.** Каждое занятие содержит произнесение вслух (шэдоуинг, запись, «скажи сам»).
4. **Разнообразие вместо монотонности.** Один и тот же тип упражнения идёт подряд не дольше ~3 минут, потом смена формата.
5. **Без наказаний.** Нет «жизней», которые отнимаются, нет стыда за ошибки. Ошибка — повод повторить, а не проиграть.
6. **Честные данные.** Весь китайский контент проверяется (раздел 9.4). Лучше меньше слов, но без ошибок в тонах.
7. **Всё локально.** Без аккаунтов, бэкенда, аналитики и рекламы. Данные только на устройстве пользователя плюс ручной бэкап.
8. **Интерфейс на русском.** Китайский — упрощённые иероглифы, стандартный путунхуа (материковый Китай).

## 3. Платформа и стек

- **Тип:** PWA (Progressive Web App) — открывается в браузере, устанавливается на главный экран телефона, работает офлайн.
- **Стек:** Vite + React + TypeScript (strict). Стили — Tailwind CSS или CSS-модули на выбор, но с единой системой дизайн-токенов (раздел 10).
- **Библиотеки (проверь актуальные версии и лицензии перед установкой):**
  - `dexie` — IndexedDB;
  - `ts-fsrs` — алгоритм интервального повторения FSRS;
  - `vite-plugin-pwa` — service worker, манифест, офлайн;
  - `pinyin-pro` — только для **проверки** пиньиня при сборке данных, не как источник истины;
  - `pitchy` — определение высоты тона для визуализации (фаза 4);
  - `hanzi-writer` — порядок черт (фаза 4);
  - `vitest` — юнит-тесты; `@playwright/test` — e2e на мобильном вьюпорте.
- **Скрипты подготовки данных** — Python 3 (`scripts/`), в частности генерация аудио (раздел 7).
- **Никаких** внешних запросов во время работы приложения, кроме загрузки собственных статических файлов.

**Что должно быть установлено у пользователя** (опиши это в README простыми словами — пользователь инженер, но не веб-разработчик, скорее всего Windows): Node.js LTS, Git, Python 3. Дай команды для Windows (PowerShell) и отдельно для macOS/Linux.

**Запуск и хостинг:**
- Локально: `npm run dev -- --host` → пользователь открывает приложение на телефоне в той же Wi-Fi сети по адресу компьютера. Опиши это в README.
- Постоянно: GitHub Pages через GitHub Actions (учти `base` в конфиге Vite). Пользователь находится в России, поэтому не используй хостинги и CDN, доступ к которым там может быть нестабилен. В README предупреди, что доступность хостинга стоит проверить с телефона.
- Шрифты и все ассеты — **самохостинг** внутри проекта, без Google Fonts по сети.

## 4. Структура курса

Курс состоит из **ступеней** (метафора ракеты, раздел 6.2). Внутри ступени — **этапы** (юниты) по 5–7 занятий.

| Ступень | Содержание | Примерные сроки при 30–45 мин/день |
|---|---|---|
| 0. «Стартовый стол» | Пиньинь, инициали, финали, 4 тона + нейтральный, тоновые пары, сандхи | недели 1–3 |
| 1. «Первая ступень» | HSK 1: знакомство, числа, время, семья, еда, покупки | месяцы 1–4 |
| 2. «Вторая ступень» | HSK 2 + начало сюжета «Командировка» + модуль «Инженер» (базовый) | месяцы 4–8 |
| 3. «Выход на орбиту» | HSK 3 + рабочие ситуации + модуль «Инженер» (расширенный) | месяцы 8–12 |

Следующая ступень открывается, когда пройдены все этапы предыдущей. При этом пользователь может вручную открыть любой этап (без блокировки «насильно»).

### 4.1. Ступень 0: пиньинь и тоны (детально)

Это самая важная часть. Этапы:

1. **Четыре тона + нейтральный.** Объяснение с графиком высоты (шкала Чао, 1–5): 1-й 55, 2-й 35, 3-й 214 (в речи чаще «низкий» 21), 4-й 51. Упражнения на слух на знакомых слогах (mā má mǎ mà ma).
2. **Финали** (a o e i u ü, дифтонги, носовые -n / -ng).
3. **Инициали**, сгруппированные по трудности для русскоязычных.
4. **Тоновые пары** — все 20 комбинаций двусложных слов (4×4 + 4 с нейтральным вторым слогом), с реальными словами.
5. **Изменение тонов (сандхи):** 3+3 → 2+3 (你好 nǐ hǎo звучит как ní hǎo); 不 перед 4-м тоном → bú (不是 bú shì); 一: yī отдельно/в конце/в порядковых, yí перед 4-м (一个 yí ge), yì перед 1–3-м (一天 yì tiān).
6. **Итоговый «предстартовый тест».**

**Трудности русскоязычных — отдельные мини-уроки и упражнения на минимальные пары:**
- Придыхание вместо звонкости: b/p, d/t, g/k, z/c, zh/ch, j/q. Русский различает б/п по звонкости, китайский — по придыханию; китайское b — это глухое «п» без придыхания, p — «п» с сильным выдохом.
- Ретрофлексные zh, ch, sh, r против z, c, s и против j, q, x.
- ü (как немецкое ü / французское u), в том числе в ju, qu, xu, yu, где точки не пишутся.
- Звук e (не русское «е»), -ng против -n, финаль -i после z/c/s и zh/ch/sh/r.
- Интонация: русскоязычные «накладывают» фразовую интонацию на тоны и сглаживают 3-й тон. Отдельные упражнения на тоны внутри вопроса и восклицания.
- **Не использовать кириллическую транскрипцию (систему Палладия)** для обучения — только пиньинь. Один раз объяснить, почему: кириллица скрывает придыхание, тоны и многие звуки.

## 5. Экраны и функции

### 5.1. «Пуск» — ежедневное занятие (главный экран)

Одна большая кнопка «Начать пуск». Занятие собирается автоматически из блоков с таймером. По умолчанию ~40 минут, в настройках 20 / 30 / 45:

| Блок | Время (по умолчанию) | Что внутри |
|---|---|---|
| Разминка | 3 мин | Мини-игра на тоны (раздел 6.1) |
| Повторение | 10 мин | Карточки FSRS, которые пора повторить |
| Новое | 12 мин | Урок текущего этапа: новые слова, фразы, объяснение, упражнения |
| Эхо | 10 мин | Шэдоуинг фраз и диалогов этапа |
| Скажи сам | 5 мин | Произнести вслух по-китайски + самооценка, или запись и сравнение |

Правила:
- Блоки можно пропустить; занятие можно прервать и продолжить позже в тот же день.
- Если карточек на повторение слишком много (больше ~150), приложение не заваливает ими, а ограничивает количество и сообщает об этом.
- В конце — экран итогов: время, новые слова, точность тонов, «Δv» (очки, раздел 6.2), весёлая реплика маскота.

### 5.2. «Карта полёта» — курс

Визуальная карта ступеней и этапов с прогрессом. У каждого этапа — список слов, фраз и диалогов, кнопка «пройти заново».

### 5.3. Словарь

- Все изученные и встреченные слова: иероглифы, пиньинь с тонами, перевод, пример, аудио.
- Поиск по русскому, пиньиню (с тонами и без, цифрами `ma3` и значками `mǎ`), иероглифам.
- Фильтры: ступень / этап / HSK / модуль «Инженер» / «трудные».
- Кнопка «добавить в повторение».

### 5.4. Тренажёр тонов (отдельный раздел)

Свободная тренировка вне занятия: одиночные слоги, тоновые пары, минимальные пары инициалей и финалей. Статистика ошибок — **тепловая карта 5×5 тоновых пар**: какие пары путаются чаще всего. Упражнения автоматически чаще дают слабые пары.

### 5.5. Плеер «Эхо» (шэдоуинг)

- Воспроизведение фразы или диалога: скорость 0.75 / 1.0, повтор фразы, автопауза между фразами длиной «время фразы × 1.2» для повторения вслух.
- Переключатели: показать или скрыть иероглифы, пиньинь, перевод. Режим «только звук».
- Запись своей попытки (MediaRecorder) и воспроизведение «образец → я → образец».
- Фаза 4: график высоты тона (раздел 7.4).

### 5.6. Сюжет «Командировка»

См. раздел 6.3.

### 5.7. Статистика

Минуты по дням (график), серия дней, выученные слова по ступеням, удержание (retention) по FSRS, точность тонов по тоновым парам, прогноз «до HSK 1/2/3».

### 5.8. Настройки

Длительность занятия; скорость аудио по умолчанию; голос (женский/мужской); показ иероглифов (всегда / после ответа / никогда); цвета тонов вкл/выкл; звуковые эффекты вкл/выкл; вибрация вкл/выкл; тёмная/светлая/системная тема; экспорт и импорт бэкапа; сброс прогресса (с подтверждением).

## 6. Весёлость (обязательное требование)

Цель — чтобы хотелось зайти завтра. Но без манипулятивных приёмов: никаких «ты потеряешь всё», грустных маскотов и навязчивых уведомлений.

### 6.1. Мини-игры

Каждая игра — короткая (1–3 минуты), с личным рекордом, комбо и быстрыми звуковыми и визуальными откликами. Все игры используют только уже пройденный материал.

1. **«Тон-тир».** Звучит слог — пользователь свайпает в направлении тона (→ ровный, ↗ восходящий, ∨ «ямка», ↘ нисходящий, тап — нейтральный) или жмёт одну из кнопок. Темп постепенно растёт, серия верных ответов даёт множитель.
2. **«Пинг-понг пар».** Звучит двусложное слово — выбрать тоновую пару. Слабые пары пользователя попадаются чаще.
3. **«Близнецы».** Минимальные пары (zhī/zī, bā/pā, lǜ/lù, fān/fāng): что прозвучало?
4. **«Скорострел».** 60 секунд, слово → перевод или аудио → слово. Рекорд за всё время и за неделю.
5. **«Сборка».** Собрать фразу из перемешанных слов (порядок слов), затем прослушать и повторить вслух.
6. **«Обратный отсчёт».** Финал каждого этапа — сцена-«босс»: диалог, где пользователь выбирает или произносит реплики. Успех — анимация успешного пуска ракеты. Неудача — «пуск перенесён», можно сразу повторить, без штрафа.

### 6.2. Ракетная метафора и прогресс

Пользователь — будущий инженер ракетно-космической отрасли, поэтому игровая обёртка построена вокруг пуска ракеты:

- Ежедневное занятие — **«пуск»**, серия дней — **«дней на орбите»**.
- Очки — **Δv** (дельта-v): начисляются за время, точность, произнесение вслух.
- Ступени курса — **ступени ракеты**. Ракета на карте полёта визуально собирается по мере прохождения.
- **«Резервный день»:** 1 пропуск в неделю не обрывает серию.
- **Достижения** с юмором, например «Первый 你好», «Сто верных третьих тонов», «Ни одной ямки мимо», «Сказал вслух 1000 раз», «Ночной пуск» (занятие после 23:00).

Все названия и метафоры хранить в одном файле словаря интерфейса (`src/i18n/ru.ts`), чтобы их легко менять.

### 6.3. Сюжет «Командировка»

Сквозная история, начинается со ступени 1 (простые сцены) и развивается дальше. Российский инженер-стажёр едет в командировку к китайскому партнёру. Эпизоды привязаны к лексике этапов:

1. Знакомство (你好，我叫…，我是工程师。)
2. Аэропорт и такси
3. Гостиница
4. Столовая: заказать еду, 辣不辣？
5. Экскурсия по заводу
6. Совещание: представиться, числа, даты, «повторите, пожалуйста», «говорите медленнее»
7. Испытания
8. Прощальный ужин и 干杯！

Постоянные персонажи с характерами (например, весёлый китайский коллега, строгий главный инженер, которого по местному обычаю называют «фамилия + 工», например 王工). В репликах — лёгкий добрый юмор. У каждого персонажа свой голос TTS.

Внутри эпизодов — **короткие культурные вставки** (визитки, обращения, тосты, чаепитие, офисный этикет, как вежливо отказаться) по 2–3 предложения.

### 6.4. Маскот

Оригинальный маскот — маленькая ракета **小火 (xiǎo huǒ, «Огонёк»)**. Простая SVG-иллюстрация собственного рисунка, 4–5 состояний (радуется, думает, подмигивает, «ой», празднует). Короткие реплики в итогах занятия и при ошибках, **добрые и смешные, не пассивно-агрессивные**. Пул из 50+ реплик, чтобы не повторялись часто.

### 6.5. Мелочи, которые делают весело

- Короткие приятные звуки (правильно / ошибка / комбо / пуск), выключаемые.
- Вибрация на Android (`navigator.vibrate`), если поддерживается.
- Примеры предложений с юмором и из жизни студента и инженера, а не только «это книга».
- Иногда — «бонусная карточка»: забавный факт или полезное интернет-словечко (например, 666, 牛), помеченное как разговорное.
- Мнемоники для иероглифов (фаза 4) — короткие, образные, смешные.

## 7. Аудио

Самая тонкая часть. Без качественного звука приложение бесполезно.

### 7.1. Источники звука, по приоритету

1. **Одиночные слоги с тонами** (ступень 0, тон-тир, близнецы) — записи носителей из открытого набора. Например, проверь репозиторий `hugolpz/audio-cmn` на GitHub и аналоги. **Обязательно проверь лицензию**, добавь атрибуцию в раздел «Об приложении» и в README. Если подходящего набора с понятной лицензией нет — сообщи пользователю и используй вариант 2.
2. **Слова, фразы, диалоги** — заранее сгенерированные нейросетевыми голосами файлы. Скрипт `scripts/generate_audio.py` использует пакет `edge-tts`: голоса `zh-CN-XiaoxiaoNeural` (жен.) и `zh-CN-YunxiNeural` (муж.), для персонажей сюжета — разные голоса. Предупреди в README, что это неофициальный доступ к сервису Microsoft для личного использования и что ему нужен интернет **при сборке**, не при использовании.
3. **Запасной вариант** — Web Speech API (`speechSynthesis`, `lang="zh-CN"`). Использовать только если файла нет. Обнаруживать наличие китайского голоса; если голоса нет — показать понятную подсказку, как установить китайский голос в Android, iOS и Windows.

### 7.2. Правила генерации

- Имя файла — хэш от (текст + голос + скорость), чтобы не генерировать повторно.
- Формат — mp3 или opus с небольшим битрейтом. Оценка объёма: ~1500 слов + ~1000 фраз ≈ 20–40 МБ.
- Одиночные иероглифы TTS может прочитать не тем чтением (многозвучные иероглифы: 了, 行, 长, 的…). Для одиночных слогов не полагайся на TTS по иероглифу; для слов проверяй выборочно. Скрипт выводит список многозвучных для ручной проверки.
- Ведётся `audio-manifest.json`: текст → файл, голос, источник, лицензия.

### 7.3. Воспроизведение

- iOS Safari не проигрывает звук без действия пользователя. «Разблокировать» аудио на первом тапе (AudioContext / пустой звук).
- Предзагрузка аудио следующих 3–5 карточек, без задержки после тапа.
- Одновременно играет только один звук.

### 7.4. Произношение пользователя (фаза 4)

- **Запись и сравнение** (MediaRecorder) — работает везде, это основная функция.
- **График высоты тона:** из образца и записи пользователя извлекается кривая основного тона (`pitchy`), переводится в полутоны относительно медианы говорящего (чтобы мужской и женский голоса были сравнимы) и рисуется двумя линиями. Подпись: «это наглядная подсказка, а не оценка».
- **Распознавание речи (бета):** Web Speech API `SpeechRecognition` с `zh-CN`, только если браузер поддерживает (обычно Chrome/Edge на Android и ПК). Показывает, что распознал сервис, и сравнивает иероглифы. Честно указать в интерфейсе, что распознавание не проверяет тоны напрямую и работает через серверы разработчика браузера. Если функции нет — скрыть, а не показывать ошибку.
- Разрешение на микрофон запрашивать только при первом нажатии «записать», с объяснением зачем.

## 8. Пиньинь и тоны: правила для кода

Вынести в модуль `src/lib/pinyin/` со 100% покрытием тестами:

- Хранение в данных — **с цифрами** (`ni3 hao3`, нейтральный тон — `5`, ü — `v`), отображение — со значками (`nǐ hǎo`).
- Расстановка знака тона: на `a` или `e`, если есть; в `ou` — на `o`; иначе на последнюю гласную (`liù`, `guǐ`).
- Ввод пользователя: принимать `ma3`, `mǎ`, `ma`, `lv4`/`lü4`/`lu:4`/`lǜ`; сравнивать нормализованно. Режим «с учётом тонов» / «без учёта» для разных упражнений.
- Два вида пиньиня у слова: **словарный** (как в словаре) и **произносимый** (с сандхи). По умолчанию показывать словарный, при нажатии — произносимый, с пометкой, какое правило сработало. Сандхи 3+3 применяются внутри слова и в устойчивых сочетаниях; не пытаться строить сложную просодию целой фразы.
- Цвета тонов (по умолчанию, настраиваемые): 1 — красный, 2 — зелёный, 3 — синий, 4 — фиолетовый, нейтральный — серый. **Цвет никогда не единственный носитель информации** — знаки тонов видны всегда.
- Иероглифы всегда в элементах с `lang="zh-CN"`, иначе браузер может подставить японские или традиционные начертания глифов.

## 9. Данные

### 9.1. Модель (TypeScript)

```ts
type Word = {
  id: string;
  hanzi: string;            // 工程师
  pinyin: string;           // gong1 cheng2 shi1 (словарный)
  pinyinSpoken?: string;    // если отличается из-за сандхи
  ru: string[];             // основные значения по-русски
  pos?: string;             // часть речи
  hsk2?: 1|2|3|4|5|6;       // уровень по старой шкале HSK 2.0
  hsk3?: number;            // уровень по новой шкале HSK 3.0
  tags: string[];           // 'engineering', 'business', 'colloquial', ...
  audio?: string;
  example?: SentenceId;
  mnemonic?: string;
  reviewed: boolean;        // проверено вручную / перекрёстно
};

type Token = { hanzi: string; pinyin: string; wordId?: string; ru?: string };

type Sentence = {
  id: string;
  tokens: Token[];          // явная разбивка на слова — не сегментировать на лету
  ru: string;
  literal?: string;         // дословный перевод для понимания порядка слов
  audio: { voice: string; file: string }[];
  unitId: string;
  reviewed: boolean;
};

type Dialogue = { id: string; unitId: string; title: string; characters: string[];
  lines: { speaker: string; sentenceId: string }[]; cultureNote?: string };

type Unit = { id: string; stage: 0|1|2|3; order: number; title: string;
  goals: string[]; newWords: string[]; sentences: string[]; dialogues: string[];
  grammarNotes: { title: string; ru: string; examples: string[] }[]; boss: string };
```

Прогресс пользователя (Dexie): карточки FSRS, история ответов, статистика по тоновым парам, время по дням, достижения, рекорды игр, настройки.

### 9.2. Типы карточек FSRS

Для каждого слова заводится несколько карточек, открываются постепенно:
1. **Аудио → значение** (понимание на слух) — открывается первой.
2. **Иероглифы + пиньинь → значение.**
3. **Значение → скажи вслух** (самооценка после прослушивания образца) — главная для цели «говорить».
4. **Тоны:** слово → выбрать тоновый рисунок.
5. **Иероглифы без пиньиня → значение** — открывается только со ступени 2 или по настройке.

Оценки: «Снова / Трудно / Хорошо / Легко». Параметры FSRS по умолчанию; целевое удержание 0.9, настраиваемое.

### 9.3. Источники словаря

- Списки слов HSK — из открытых наборов (например, проверь `drkameleon/complete-hsk-vocabulary` на GitHub; сверь лицензию). Хранить уровни **и по старой (HSK 2.0), и по новой (HSK 3.0) шкале** — в разных центрах экзамены сдаются в разном формате, пользователь сам выберет цель в настройках.

### 9.4. Контроль качества контента (обязательно)

Скрипт `npm run check:content`:
- Сверяет пиньинь каждого токена с `pinyin-pro`; расхождения выводит списком (многозвучные иероглифы проверяются вручную, а не автоисправляются).
- Проверяет, что каждое предложение этапа использует только слова этого и предыдущих этапов (через `tokens[].wordId`), кроме помеченных как «новое» — правило i+1.
- Проверяет наличие аудио для всего контента.
- Выводит долю `reviewed: false`.
- Сборка падает при отсутствии аудио или битых ссылках между сущностями.

Весь китайский текст — естественный современный путунхуа, без калек с русского. Если сомневаешься в естественности фразы — лучше замени её более простой.

## 10. Дизайн

Прочитай и соблюдай навык frontend-design, если он у тебя есть. Направление для этого проекта:

- **Характер:** «инженерный журнал испытаний встречается с китайской типографикой». Чистая сетка, точные подписи, немного чертёжной эстетики (тонкие линии миллиметровки как фон отдельных экранов), но тепло и с юмором, а не сухо.
- **Одна смелая вещь** — цвета тонов. Весь остальной интерфейс сдержан, чтобы тоны «светились».
- **Иероглифы крупно**, это главный визуальный элемент карточек. Шрифт для китайского — системный стек (`"PingFang SC", "Noto Sans SC", "Microsoft YaHei", sans-serif`), без встраивания огромных CJK-шрифтов. Шрифт для кириллицы и пиньиня выбери осознанно (не дефолтный). **Проверь, что он корректно рисует ǖ ǘ ǚ ǜ и все знаки тонов**; если нет — для пиньиня отдельный шрифт.
- Избегай шаблонных решений: одинаковых скруглённых карточек с одинаковой тенью, CAPS-меток над каждым заголовком, градиентных «подложек» ради украшения.
- **Mobile-first:** основной экран — телефон 360–430 px. Главные кнопки в нижней трети экрана, в зоне большого пальца. Цели касания не меньше 44×44 px. Учитывай safe-area (вырезы экранов).
- Светлая и тёмная темы. Видимый фокус с клавиатуры, `prefers-reduced-motion`, контраст по WCAG AA.
- Анимации — только как отклик на действие (верно/неверно, комбо, пуск ракеты). Одна яркая анимация — пуск в конце этапа.
- Тексты интерфейса короткие, живые, на «ты». Кнопки называют действие: «Начать пуск», «Повторить фразу», «Записать».

## 11. Хранение, офлайн, бэкап

- Данные прогресса — IndexedDB (Dexie). При первом запуске вызвать `navigator.storage.persist()`.
- **Важно для iPhone:** Safari может удалить данные сайта, если его не открывали ~7 дней и он **не установлен** на главный экран. Показывать ненавязчивую подсказку «Установи на главный экран», пока приложение не установлено.
- **Экспорт/импорт бэкапа** — один JSON-файл. Напоминание сделать бэкап раз в 2 недели (закрываемое).
- Миграции схемы БД версионированы; обновление приложения не должно терять прогресс. Тест на это обязателен.
- Офлайн: оболочка приложения кэшируется сразу; аудио кэшируется по мере использования + кнопка «Скачать этап / ступень для офлайна».

## 12. Связка с чатом Claude

В приложении **нет** встроенного ИИ. Вместо этого кнопка **«Потренироваться с Claude»** на экране этапа и в итогах занятия: собирает текстовый промпт и копирует его в буфер обмена. Пользователь вставляет его в чат с Claude.

Шаблон промпта (в файле, легко редактируемый):

```
Я учу китайский с нуля, цель — работа (инженер, ракетно-космическая отрасль).
Сейчас я на этапе «{название этапа}», ступень {N}.
Слова, которые я знаю: {список слов с пиньинем}.
Слова, которые мне трудно даются: {трудные слова}.
Тоновые пары, в которых я ошибаюсь: {пары}.
Проведи со мной ролевой диалог по ситуации «{ситуация}».
Используй только знакомые мне слова и максимум 2–3 новых (объясни их).
Пиши иероглифы + пиньинь с тонами + перевод. Исправляй мои ошибки мягко и коротко.
Сделай это весело.
```

Встроенный вызов API Claude — вне рамок (раздел 17): он требует ключа и оплаты, а API Anthropic официально недоступен из России.

## 13. Нефункциональные требования

- Холодный старт на среднем Android-телефоне — менее 2 секунд; переход между карточками — мгновенный.
